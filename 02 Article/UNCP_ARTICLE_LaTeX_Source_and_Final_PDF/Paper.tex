\abstract{
Modeling click sequences in a mobile application can support the analysis of user behavior across interface pages and help guide future UX evaluation. This study evaluates next-click prediction in an enterprise application using 46,194 recorded click events in 4,223 sequences. Complete User IDs are assigned to training, validation, and test partitions before prefix--target examples are generated. We compare the proposed validation-selected UNCP 5 with LSTM and Transformer reference models under the same user-disjoint protocol. Mean Top-3 accuracy over three seeds is 85.09\% for UNCP 5, 78.00\% for LSTM, and 71.92\% for Transformer. These results demonstrate next-click prediction under the specified evaluation conditions; potential UX improvements require prospective user testing.
}

\section{Introduction}

\label{sec:intro}
User interaction behavior on smart mobile devices typically involves a sequence of taps or clicks\footnote{In this study, the term  \textit{click} is used instead of \textit{tap} to refer to interactions on the mobile application screen.} on touch-screen interface elements, resulting in a series of screen state transitions in response to these actions \cite{bohmer2011falling}. Predicting the next user click through machine learning models opens up new possibilities for enhancing user experience. For instance, interface elements can be reordered based on user interaction frequency, thereby improving efficiency and speeding up task completion. Furthermore, Adaptive User Interfaces (AUIs) can be dynamically activated to personalize the layout and make the interface more intuitive for future use \cite{parate2013practical}. An AUI adapts the arrangement of UI elements to the user's preferences or behavior patterns. This means components such as surveys, fund transfers, settings, and events on a page can be reordered either by the user or automatically based on usage frequency \cite{findlater2009ephemeral, tanvir2011improving}.

Numerous studies have focused on modeling user click behavior across domains such as mobile interaction \cite{lee2018click}, web navigation \cite{mao2018constructing}, advertising \cite{liu2015convolutional}, news consumption \cite{wu2019neural}, and e-commerce. Several works \cite{tanvir2011improving, browne2016adaptive, bohmer2011falling} have specifically explored user performance prediction at the application level. Zhou and Li \cite{zhou2021large} investigated computational modeling of click behavior as a foundation for adaptive UI systems. Their work focused on predicting the next UI element a user is likely to click. They developed LSTM- and Transformer-based learning models trained on user click data, taking into account click history, screen content, and current time to accurately forecast the next user action.


\textbf{Our Contribution:}
The main contributions of this study are summarized as follows:
\begin{itemize}
	\item {Model comparison:} Evaluation of transparent baselines, LSTM, GRU, Transformer, and six UNCP variants on the same held-out-user partition; the variants and their component combinations are identified in the result tables.
	
	\item {Real dataset:} Analysis of 46{,}194 click events in 4{,}223 sequences from 52 recorded User IDs, with complete User IDs held out from model fitting and preprocessing.
	
	\item {UX techniques:} Use of predicted click rankings to identify possible UX improvements for evaluation in controlled usability studies.
	
	\item {Decision support:} Examination of how predicted click rankings may help prioritize interface flows and possible design improvements for later UX investigation; efficiency and usability effects are not measured in this study.
\end{itemize}




\section{ Related Work}

In recent years, extensive research has been conducted on modeling user interactions and enhancing user experience through predictive systems. In this section, we review key studies that have contributed to this area.



%Previous works have shown that mobile user behaviors are influenced by various factors.


Baeza-Yates et al.~\cite{bohmer2011falling} proposed a predictive framework that identifies the next mobile application a user is likely to engage with. Their model utilizes a set of contextual features to predict the upcoming app interaction and subsequently reorganizes the app's menu layout based on the frequency of user access, thereby offering a more personalized experience.  Chen et al.~\cite{chen2019behavior} made significant advancements in predicting click-through rates (CTR) in Taobao's recommendation system by employing deep learning techniques. They introduced a Transformer-based recommendation model that represents user and item features as embedded vectors. These vectors are processed through a multi-layer fully connected neural network to estimate the likelihood of a user clicking on a specific item. Qin et al.~\cite{qin2020user} addressed user interest modeling by employing sequential behavior analysis in mobile applications. Their approach first selects relevant user actions from historical interaction sequences using information retrieval techniques, and then feeds them into a deep learning model for CTR prediction. This combination of retrieval-based filtering and deep learning improved the model's capacity to capture nuanced user preferences over time.

Yang et al. \cite{yang2020measuring} simulated user experience in the process of running a mobile app in their proposed model using machine learning. They used predicted app pages with the effect of time on element selection (see figure \ref{fig:PagesAndTimes}) to train neural networks, which were formed from click information of all users during a specific task process. Zhou and Li \cite{zhou2021large}, researchers at Google, designed a deep learning model based on Transformer using a dataset obtained from user interactions with a mobile application. This model predicts the next element that the user is most likely to click on, based on the user's click history and user interface information (see figure \ref{fig:examplecontacts}).
Wu et al. \cite{wu2023screen} concentrate on understanding the functionality of user interface elements. This method enables better analysis by mapping UI elements to previous examples, incorporating their semantic properties, appearance, text, and how they function. The model is used for generating in-app tutorials, searching for UI elements, and testing them. For example, this algorithm can identify that a UI element on a page is a button with the text `Login` or a text field with the text `Sign Up`.

Sun et al. \cite{sun2022meta} introduced a new GUI-based architecture (GUITOD) that is capable of directly interacting with software using graphical tools instead of complex textual commands. The operations performed include clicking on buttons, text fields, search fields, and similar elements. Ultimately, by clicking on these elements, actions are carried out based on the scenario and user flow. Additionally, it is used for training dialogue models in mobile applications. This model also predicts the next action of the user. It is widely used for performing specific tasks such as hotel reservations, calendar scheduling, and online shopping. Wu et al.\cite{wu2023never} trained machine learning models to predict semantic information about user interfaces to make mobile apps more accessible and automated. They introduced a Never-ending UI Learner model, which automatically extracts real apps by interacting with UI elements. This model helps improve the understanding of UI elements in the app. Feng et al.\cite{feng2023video2action} have made mobile app tutorial videos a popular method for users to learn various features. To make these videos easily understandable for users, video creators need to annotate different actions in the video. They introduced an approach called Video2Action, based on image processing and deep learning, which automatically predicts and highlights the click locations in the video. Feng et al.\cite{feng2024mud} introduced a novel approach to automatically extract UI data from Android apps using Large Language Models (LLMs). This model is used for UI modeling and element identification. Zhou et al.\cite{zhou2024encode} proposed a two-stage long-term sequence modeling approach, consisting of offline extraction and online inference, which is used to familiarize with user interests for predicting associations with target items.

Related work on intelligent optimization provides additional systems context. Addula et al.~\cite{addula2024kookaburra} proposed a hybrid Kookaburra--Pelican optimization approach for dynamic cloud load balancing, targeting improved workload distribution and resource utilization. Although that study addresses infrastructure optimization rather than next-click prediction, it illustrates how hybrid optimization can support adaptive system decisions. We cite it as broader background only, not as evidence for predictive accuracy or UX improvement in the present study.

Human-centered AI is also relevant when predictive systems are deployed in workplace settings. Meduri et al.~\cite{meduri2024human} studied how personalization, employee training, and feedback shape the effects of AI-supported workload management and emphasized that human-centered implementation matters beyond model performance. We cite this work as contextual motivation for careful, human-centered UX analysis; it is not used as evidence that the present next-click model improves employee well-being or usability.


As reviewed in our Related Work section, prior studies have examined next-action prediction and adaptive interfaces. The present study contributes a leakage-aware comparison of next-click models on an enterprise clickstream and explores predicted rankings as a possible decision-support signal for UX researchers. We do not claim that the model automates UX evaluation or improves usability; those outcomes require comparison with established UX methods and direct user-study evidence.

\subsection{Data Preprocessing}
Click events were ordered by recorded User ID and event time where timestamps were valid. The primary analysis retains consecutive clicks on the same element because repetition may reflect delayed feedback, confusion, accessibility difficulty, or frustration. The analytic dataset contains 46,194 click events in 4,223 sequences from 52 recorded User IDs. Session construction and its sensitivity to inactivity thresholds are described below.

\begin{itemize}
	\item
	
	This method defines a user's click sequence from the first click until a set expiry time typically two minutes of inactivity. If no click occurs within two minutes, the sequence from the first to the last click is stored (Figure \ref{fig:ExpireTime}).
	The 120-second and 240-second inactivity cutoffs are evaluated as alternative session-construction settings. They are not assumed to be universal mobile-session durations, and no claim of statistical equivalence is made.
	\begin{center}
	\begin{figure}[!h]  \centering \includegraphics[width=0.6\linewidth]{expire_time}  \caption{Illustration of the 120-second inactivity cutoff evaluated for click-sequence construction.} \label{fig:ExpireTime} \end{figure}
		\end{center}
	
	\item
	Sequence Based on User App Sessions:
	A sequence was defined from the moment the user opened the app until it was closed. In this scenario, the user opened the app, clicked on various parts, and then closed the app, which was recorded as a click sequence.
\end{itemize}
The two cutoffs provide a sensitivity check around short mobile interactions rather than a literature-established optimum. In the repeat-inclusive export, 4,185 rows (44,823 clicks) have aligned timestamps for within-row gap analysis. Splitting these rows at gaps greater than 120 and 240 seconds yields 4,306 and 4,263 sequences, respectively, without changing the 44,823 observed clicks. Mean sequence lengths are 10.41 and 10.51 clicks, respectively (median 5; 95th percentile 25 in both settings). The corresponding numbers of next-click targets are 40,517 and 40,560. This analysis excludes rows with unusable timestamp alignment; it does not reconstruct the complete original event log or establish that either cutoff is optimal. \subsection{Data Modeling}
To model the data, a dataset of user click sequences is obtained after preprocessing. These click sequences are initially performed by a user with a defined expiration time, and the user identifier is recorded in the first column. The second column contains the name of the page where the element was clicked. Subsequently, the user's click sequence across different pages is displayed, with the clicked element in each page documented accordingly. Finally, the date and time of these click sequences are recorded. The event table supports sequence construction and retrospective diagnostics; the evaluated predictor receives only the observed click-label prefix, not the User ID, page labels, or timestamps.

\subsubsection{Sequence Lengths \& Time Spans} 
After restoration, sequence length ranges from 1 to 1,156 clicks (median 5; mean 10.94). Model context is capped at the last 32 observed clicks, so extremely long repeated-click runs do not increase the input length beyond the prespecified context window.

\section{Architectures for Predicting the Next User Click}
%\section{Modeling Click Behaviors}
\label{sec:model}
Following the data collection and preprocessing steps previously outlined, the architectures of two models developed for predicting the next user click are presented in the sections below.

\subsection{Modeling User Click Behavior with LSTM}
\begin{figure}
	\centering
	\includegraphics[width=1\linewidth]{lstm_arc}
	\caption{The architecture of the LSTM model, comprising layers for pages, clickable elements, user click events, tokenization, embedding, and LSTM layers.}
	\label{fig:LstmArc}
\end{figure}

A click event is characterized by attributes such as the page, the element clicked, and the time the click occurred.
The $i$-th event in the click sequence is denoted by $e_i$ and is defined as shown in (Equation \ref{ei}):
\begin{equation}\label{ei}
	e_i=[s_i, c_i, t_i]
\end{equation}

where $s_i$ represents the page in the $i$-th event, $c_i$ denotes the element that was clicked, and $t_i$ indicates the time of the event.
The page \( s_i \) consists of several clickable elements \( c_i \in s_i \), where \( 1 \leq i \leq |s_i| \) and \( |s_i| \) represents the number of clickable elements on the page. Therefore, the click sequence of a user is defined as the set \( e_{i:n} \).
\begin{equation*}\label{ein}
	e_{i:n}=\{(s_1, c_1, t_1), (s_2, c_2, t_2), \ldots, (s_n, c_n, t_n)\}
\end{equation*}

The recorded events form a click sequence (Figure \ref{fig:LstmArc}), but the revised predictive models tokenize only the observed clicked-element labels. Page and time remain in the event archive for reconstruction and retrospective analysis; neither is a model feature. The token map is fitted on the training partition and maps an unseen input label to an unknown token (Equation \ref{tokenizer4}).
\begin{equation}\label{tokenizer4}
	v_i = \operatorname{tokenizer}(c_i)
\end{equation}

Then, during embedding, the generated numerical codes are mapped to fixed-dimensional vectors so that these vectors can capture the semantic relationships between words and be used for learning (Equation \ref{embedding4}).
\begin{equation}\label{embedding4}
	embedding(v_i)= v_i \cdot w_e
\end{equation}

In this, $w_e$ is the matrix that holds the embedding weights, where $w_e \in \mathbb{R}^{V \times D}$, and its dimensions depend on the number of words in the vocabulary and the embedding dimensions. $V$ is the number of unique words in the dataset, and $D$ is the dimensionality of the embedding vector, which is a hyperparameter typically set as the number of embedding dimensions.
The first LSTM layer processes the input sequence, models the temporal relationships between the clicks, processes a sequence of vectors $v_i$, and outputs the hidden state $h_t$ (Equation \ref{llstm4}).
\begin{equation}\label{llstm4}
	h_t = l_{lstm} \rightarrow embedding(v_i)
\end{equation}

Where $h_t \in \mathbb{R}^M$ represents an $M$-dimensional space. In the model, this means that the output of each node or unit in this layer will be an $M$-dimensional vector of real numbers. In other words, if $M$ equals 128, each output vector from this layer will have 128 components. For example, in the LSTM layer in the model architecture described, if $M$ is set to 128, each hidden state (denoted as Hidden State) output from this layer will be a vector of real numbers representing the information the model acquires from the data at each step.
The revised LSTM reference implementation has one 64-unit recurrent layer; the final non-padding hidden state represents the observed prefix.
The $Dense$ layer, a fully connected layer, converts the output of the previous layers into a fixed-dimensional vector (Equation \ref{ldense4}).

\begin{equation}\label{ldense4}
	l_{dense} : dense(h_t )
\end{equation}

The $Dropout$ layer randomly disables some neurons during training to prevent overfitting and make the model more generalizable (Equation \ref{ldropout4}).

\begin{equation}\label{ldropout4}
	l_{dropout} : dropout(l_{dense})
\end{equation}

The prediction task is defined in Equation \ref{eincn4}. At inference time, the model has access only to the observed click labels up to step $n$; it ranks next-click labels from the training vocabulary.

\begin{equation}\label{eincn4}
	\hat{\mathbf p}_{n+1}=f_{\theta}(c_{\max(1,n-L+1):n}),\qquad \hat c_{n+1}=\operatorname*{arg\,max}_{c}\,\hat p_{n+1}(c),\quad L=32
\end{equation}


Here $c_{\max(1,n-L+1):n}$ is the last $L=32$ observed click labels (or the shorter available prefix), $f_{\theta}$ returns a probability distribution over next-click labels, and $\hat c_{n+1}$ is its highest-ranked label. The actual next click $c_{n+1}$ is the evaluation target. The destination page $s_{n+1}$ and event time $t_{n+1}$ are known only after that event and are never supplied to $f_{\theta}$. Recorded destination pages are used solely for retrospective page-level diagnostics.

\subsection{Modeling User Click Behavior with Transformer}
First, a semantic representation of the clicked element in each click event is extracted to better understand the features of the elements and the user's click behavior.
Then, a sequence of click events is modeled to encode the user's click history.
Finally, based on the encoded click history, the reference model ranks next-click labels in the training target vocabulary (Figure \ref{fig:TransformerArc}). It is not given the future destination page or a page-specific candidate mask.

%The $i$-th event in the click sequence is denoted by $e_i$ and is defined as (Equation \ref{ei}):

%Where $s_i$ represents the page in the $i$-th event, $c_i$ is the clickable element that was clicked, and $t_i$ is the time of the event. The page $s_i$ consists of a number of clickable elements $c_i \in s_i$, where $1 \leq i \leq |s_i|$, and $|s_i|$ denotes the number of clickable elements on the page. Therefore, the user's click sequence is defined as the set $e_{i:n}$:

%\begin{equation*}\label{ein}
%	e_{i:n}=\{(s_1, c_1, t_1), (s_2, c_2, t_2), \ldots, (s_n, c_n, t_n)\}
%\end{equation*}


%In this formula, the user's click events are expanded and written as events from $i$ to $n$ to form a click sequence. Next, tokenization is applied to the elements of the user's click sequences ${e_{i:n}}$, converting pages and clickable elements into numerical codes, allowing the model to process them (Equation \ref{tokenizer5}). The role of the tokenizer is to map each element to a unique number, enabling the tokens to be provided as numerical input to the model.

%\begin{equation}\label{tokenizer5}
%	v_i = Tokenizer ({e_{i:n}})
%\end{equation}

The Transformer uses the same observed-click tokenization as the LSTM reference model (Equation \ref{tokenizer4}).
In the following, the focus shifts to the embedding layer.

Subsequently, in the embedding step, the generated numerical codes are transformed into fixed-dimensional vectors so that these vectors can capture the semantic relationships between the elements and be used for learning (Equation \ref{embedding5}).

\begin{equation}\label{embedding5}
	\mathrm{Embed}_i = \mathrm{Embed}(c_i) 
\end{equation}

Only the observed click label is embedded. The page and timestamp are retained in the event data for retrospective analyses, not concatenated with the model input.

In the next step, positional encoding is added to the embedded vector to preserve the order of clicks in the sequence, as the Transformer model inherently does not encode the sequence order (Equation \ref{PositionalEncoding44}).

\begin{equation}\label{PositionalEncoding44}
	Embed_i' = Embed_i + {PositionalEncoding}(i)
\end{equation}

\smallskip
The position-aware embeddings are projected with learned matrices \(W_Q\), \(W_K\), and \(W_V\) to form the query \(Q\), key \(K\), and value \(V\) representations. Scaled dot-product attention applies a row-wise softmax to the query--key scores and uses the resulting weights to combine the values (Equation \ref{Attentionmchm4}).

\begin{equation}\label{Attentionmchm4}
	Attention (Q, K, V) = {Softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V
\end{equation}
\smallskip
To compute the dot product between the matrices $Q$ and $K$, the calculation \( QK^T \) is performed first. Here, \( K^T \) is the transpose of the matrix \( K \), where its rows and columns are swapped. This allows the dot product between each Query and each Key to be computed.
For normalization, the values obtained from the dot product \( QK^T \) are divided by \( \sqrt{d_k} \), where \( \sqrt{d_k} \) is the dimensionality of the key. This helps reduce fluctuations in large values and makes the model train more effectively. The reason for using \( \sqrt{d_k} \) is that as the number of dimensions increases, the dot product values become larger, and dividing by \( \sqrt{d_k} \) helps balance these values.
Next, a fully connected neural network $x$ is applied independently to each position in the sequence and normalized to improve the stability of the training process.
In the next step, the remaining connections are added to the network to prevent the vanishing gradient problem. The encoder layers, which include self-attention and fully connected neural networks, are repeated multiple times. This repetition allows the model to learn more complex datasets (Equation \ref{Repeating Encoder Layers}).

% Repeating Encoder Layers
\begin{equation}\label{Repeating Encoder Layers}
	H = {StackedEncoderLayers}(E')
\end{equation}

The repetition of encoder layers is considered one of the key principles in the Transformer model. This means that instead of using a single encoder layer, multiple encoder layers are stacked. This approach allows the model to learn more complex and higher-level features from the data.
It is indicated as the final output after passing through all the encoder layers. These vectors represent higher-level representations of the inputs, which can be utilized for subsequent stages such as computation and predicting the next click.
In the next step, the final hidden state, which is the output of the stacked encoder layers, is passed through a $softmax$ layer to produce a probability distribution, $Prob_{n+1}$, over the potential next clicks (Equation \ref{Calculating Probabilities for the Next Click}).

% Calculating Probabilities for the Next Click
\begin{equation}\label{Calculating Probabilities for the Next Click}
	Prob_{n+1} = {Softmax}(H)
\end{equation}

Finally, the Transformer model is used to predict the probability of which element on the screen, $c_{n+1}$, the user is likely to click on in the $(i+1)$-th step, and to determine the function $f$. The $argmax$ function returns the position or index with the highest probability value (Equation \ref{Predicting the Next Click}).
% Predicting the Next Click
\begin{equation}\label{Predicting the Next Click}
	UNCP{c_{n+1}} = argmax(Prob_{n+1})
\end{equation}


\subsection{Proposed UNCP Hybrid}
The proposed User Next Click Predictor (UNCP) preserves the click-sequence input used by the preceding models. A shared 32-dimensional click embedding feeds two parallel branches: a 64-unit GRU for short transition patterns and a two-layer, four-head Transformer for longer contextual dependencies. The final real-token Transformer state is projected to 64 dimensions. A learned sigmoid feature gate mixes the GRU and Transformer states elementwise; layer normalization and dropout precede the global click classifier. Neither future clicks, user identity, page identity, nor timestamps are model inputs. The individual operations are established building blocks; the contribution claimed here is their task-specific gated combination and its leakage-aware evaluation, not universal or first-ever architectural novelty.

\paragraph{UNCP 2 graph-aware extension.} UNCP 2 constructs a weighted, undirected click-transition adjacency from encoded training prefixes only, adds self-loops, and applies symmetric degree normalization. One graph propagation step transforms the shared 32-dimensional element embeddings; the resulting graph-aware token vectors feed a 64-unit GRU and a two-layer, four-head Transformer. A masked mean of observed graph token vectors forms a third context state. A learned feature gate combines the GRU state with the average of the Transformer and graph states, followed by layer normalization, dropout, and global classification. The validation and test clicks do not enter graph construction. This is a task-specific combination of established graph, recurrent, and attention operations; the observed advantage is limited to the reported dataset and split.

\paragraph{UNCP 3 and UNCP 4 exploratory variants.} UNCP 3 combines a GRU, Transformer, and a plain-PyTorch structured state-space duality (SSD) recurrence inspired by Mamba-2; it does not use the official optimized Mamba-2 kernel. UNCP 4 combines typed page--element graph attention, a training-only transition graph, a GRU, an adaptive fusion gate, and candidate masking. Its mask uses the last observed click's inventory page as a proxy for the current page, augmented with training-observed successors; 33 of 93 click-label strings lack an exact inventory match and use an unrestricted fallback. Neither variant improved on UNCP 2 in the held-out-user experiment, so they are retained as transparent exploratory comparisons rather than selected as the final predictor.

\paragraph{UNCP 5 adaptive transition fusion.} UNCP 5 combines the trained UNCP 2 probability vector with a smoothed back-off transition distribution over the last one to four observed clicks. Transition counts and the global smoothing prior use training examples only. The transition weight is a sigmoid function of log transition support and the difference between the two predictive entropies; the final probability vector is their convex combination. We selected the three gate coefficients from a fixed grid of 76 rules by mean validation Top-3 across seeds 11, 23, and 37, breaking ties by validation Top-1 and negative log-likelihood. Only after freezing that choice did we evaluate the held-out users. Thus UNCP 5 is an adaptive probability-level ensemble, not a newly trained end-to-end neural architecture. No future page, timestamp, click, or test label is used to build the transition model or select its gate.

\paragraph{UNCP 6 repeat-aware dual-scale model.} One GRU encodes the complete observed click prefix. A second GRU encodes consecutive runs after repeated labels are compressed, with each run length embedded as a feature. A learned gate combines the two states. The next-click distribution factorizes into a repeat-versus-switch probability and a classifier over elements conditional on switching; the repeat option is the last observed label. No future click is used in run construction. Three fixed-seed fits on the same user-disjoint split reach 84.08\% mean Top-3, below UNCP 5's 85.09\%. On the 1,541 repeated-click targets, their Top-3 values are 94.09\% and 94.07\%, respectively; on 9,292 switch targets they are 82.42\% and 83.60\%. This diagnostic prevents a gain on repeats from being mistaken for better prediction of changed actions.

\subsection{Potential Decision Support for UX Analysis}
The evaluated models rank likely next clicks from previously observed click sequences. These rankings may help UX researchers identify recurrent transitions, unexpected paths, and interface elements that merit inspection. They do not measure user intent, task success, cognitive load, satisfaction, or usability, and they are not equivalent to conventional UX testing. Whether they reduce evaluation time or effort must be established in a prospective comparison with an existing UX workflow.

\begin{itemize} \item \textbf{Supporting inspection of interaction flows:}
	Observed click sequences and predicted next-click rankings can be used to flag common or unexpected paths for later review. The model cannot determine from clickstream data alone whether a task was completed correctly or why a user selected an element. Figure \ref{fig:PredictionNextUserClick} illustrates the prediction task rather than a completed usability test. \end{itemize}

\subsection{Evaluation Metrics}
Evaluation metrics are used to assess the performance of different models. These metrics help determine how well the models have performed and whether they can make accurate predictions. Several metrics are calculated to evaluate the quality of predictions for each method, which are listed below.

The primary test holds out complete User IDs. We assigned all sequences of each recorded User ID to exactly one of the training, validation, or test partitions before creating overlapping click-prefix examples. The 46,194 figure counts click events, whereas the split counts below are supervised next-click targets. A sequence of length $L$ produces $L-1$ targets; therefore, 46,194 events across 4,223 sequences produce $46{,}194-4{,}223=41{,}971$ targets. The fixed split contains 32, 9, and 11 User IDs, respectively ($32+9+11=52$), and yields 25,399 training, 5,739 validation, and 10,833 test targets ($25{,}399+5{,}739+10{,}833=41{,}971$). Automated protocol checks confirmed that no User ID or source sequence occurs in more than one partition. The vocabulary, popularity counts, transition frequencies, and smoothing priors are derived only from training data. Validation data select checkpoints and the UNCP 5 fusion rule; the test partition is evaluated after those choices are fixed. These checks and the split manifest accompany the executable experiment files.

For the ``Uniform expected'' baseline, each test target is assigned equal probability over the evaluation candidate vocabulary. If the candidate set has size $K$, sampling uniformly without replacement gives an expected Top-1 accuracy of $1/K$ and an expected Top-3 accuracy of $\min(3,K)/K$. The reported 1.10\% Top-1 and 3.30\% Top-3 values therefore correspond to the 93-label global candidate vocabulary ($1/93$ and $3/93$, rounded to two decimals). This analytical expectation is not estimated from random draws. Page-conditioned uniform diagnostics are reported separately because their candidate sets and page availability are distinct from the global-label task.

\subsubsection{Top-K Accuracy:}
In this metric, the model's accuracy is calculated based on the number of times the target element appears among the top K predictions of the model. For example, to compute `Top-1 Accuracy` and `Top-3 Accuracy,` the number of times the target element appears within the first and third predictions of the model, respectively, is reported. The higher the value of this metric, the better, as it indicates that the model has performed better in identifying the target elements.

\subsubsection{Absolute Ranking Position:}
This metric refers to the ranking position of the target element among all predictions. The lower the value of this metric, the better, as it indicates that the target element is placed in a higher position among the predictions.

\subsubsection{Relative Ranking Position:}

A relative ranking metric divides the target's absolute rank by the number of candidate elements. Lower values indicate a better rank. This metric complements Top-K accuracy by describing the target's position relative to the candidate-set size, as discussed in \cite{zhou2021large}.

In addition to micro Top-1 and Top-3 accuracy, we report macro averages across held-out User IDs and target labels, results by recorded page and by training-label frequency group, and candidate-set diagnostics. Neural models are trained with seeds 11, 23, and 37; tables show the mean and sample standard deviation across these runs. For selected paired comparisons, we resample held-out Users as clusters to obtain exploratory confidence intervals and use paired User-level tests with multiplicity correction. Page labels recorded with the eventual click are used only for retrospective diagnostics, not as inference-time inputs. Within-row 120- and 240-second gap refinements and a collapsed-repeat variant assess preprocessing sensitivity. On the same grouped-User-ID assignment, the first-order Markov Top-3 scores for the two gap settings are 65.07\% and 65.10\%, and the fourth-order back-off Markov scores are 79.39\% and 79.48\%, respectively (10,798 and 10,804 test targets). These are descriptive comparisons on changed target sets, not statistical evidence of equivalence or causal threshold effects. The LSTM and Transformer scores reported for the earlier, smaller aligned-event reconstruction are not attributed to this repeat-inclusive sensitivity analysis.

\subsection{Data Preparation}
The original implementation expanded 4,216 recorded sequences into overlapping prefix--target examples and then randomly split those examples. A reconstruction showed that 6,061 of 6,215 historical test examples shared their source sequence with training, and all 52 recorded User IDs occurred in both partitions. The historical 88.91\% LSTM Top-3 result is therefore retained only as context and is not used as evidence of unseen-user generalization. After repeated-click restoration, the revised dataset contains 46,194 click events in 4,223 sequences. Because the first event of each sequence supplies context but has no preceding click from which to form a target, these data produce $46{,}194-4{,}223=41{,}971$ next-click targets.

For the revised primary evaluation, complete User IDs are assigned before prefix generation: 32 IDs for training, 9 for validation, and 11 for testing, yielding 25,399/5,739/10,833 next-click targets. The User ID counts sum to 52 and the target counts sum to 41,971, exactly matching the totals above. Vocabulary and frequency statistics are fitted on training data only, validation loss selects checkpoints, and targets unseen during training are scored incorrect. Neural models are run with seeds 11, 23, and 37. A secondary chronological analysis uses only rows with aligned, valid timestamps; because its cohort differs, it is reported separately rather than interpreted as an improvement over the user-disjoint test.

\subsection{Proposed UX Improvements}
The predicted rankings and observed click patterns motivated possible changes to the `Settings,` `Home,` `Marketplace,` and `Users` pages. These included prioritizing frequently used Settings items, reconsidering the order of Home navigation icons, adding purchase-based sorting on Marketplace, and providing a coin-balance ordering option on Users. These proposals illustrate how prediction may inform design review; the study did not measure whether they improved usability or reduced evaluation effort.

The archived clickstream contained frequent clicks on the `Close` icon in the status-entry menu of the organizational thermometer. This pattern suggests that repeated presentation of the menu merits investigation. Possible design responses include a `Do not show again` option, a temporary dismissal period, or administrator-configurable display timing. The click log alone does not establish that the menu caused annoyance or that these changes would improve the experience.

The toolbar also allows status registration at any time. This observation may inform a review of early-session interaction and feature visibility, but the available data do not measure attention, loyalty, satisfaction, or the reason a user leaves the application.

These proposed improvements are informed by observed click patterns. Recorded outcomes from the stated retest are unavailable; therefore, this study does not claim that task success, satisfaction, sequence length, or usability improved. A prospective controlled user study is required to evaluate those outcomes.

Future evaluation should test the proposed Settings ordering, Home navigation, Marketplace sorting, Users ordering, and thermometer dismissal options with comparable tasks on the existing and redesigned interfaces. A controlled study can measure task success, completion time, navigation errors, repeated or backtracking clicks, and validated usability and satisfaction scores. First-click tasks and card-sorting exercises should be conducted as distinct user studies where relevant. This would determine which proposed changes help users and whether model-guided inspection saves researchers time.

\section{Conclusion and Future work}
This study shows that next-click rankings can be learned from the enterprise application clickstream and used to prioritize interaction paths for UX inspection. The revised primary dataset retains repeated-click behavior and contains 46,194 events in 4,223 sequences. Under the held-out-user protocol, validation-selected UNCP 5 reaches the highest mean Top-3 accuracy, 85.09\% over three seeds, followed by repeat-aware UNCP 6 at 84.08\%, graph-aware UNCP 2 at 83.58\%, the original UNCP at 82.30\%, and Markov-4 at 79.91\%. The paired UNCP 5--UNCP 2 difference is 1.51 percentage points, with an exploratory held-out-user cluster bootstrap interval of 1.03--1.77 points. UNCP 6 did not improve overall accuracy or switch-target Top-3 relative to UNCP 5. These are demonstrated prediction results. The study does not demonstrate a causal improvement in UX, reduced UX-evaluation time or effort, increased user satisfaction, or scalable replacement of first-click testing, card sorting, and controlled usability evaluation. Such outcomes require a prospective controlled or A/B study that reports task success, completion time, errors, abandonment, and validated usability and satisfaction measures.

This study has several limitations. Generalizability is limited by evaluation on one enterprise Android application and an uneven cohort of 52 recorded User IDs, which are not confirmed to represent 52 distinct people. The user-disjoint evaluation on 11 held-out User IDs tests transfer to unseen User IDs within this application only. It does not establish performance for other interfaces, organizations, user populations, devices, operating systems, or application categories. Timestamp and label-quality problems, the absence of recorded post-redesign outcomes, and the lack of a formal controlled UX study further constrain interpretation. Within the available data and resources, this revision prioritized leakage correction, transparent baselines, and uncertainty estimates. Future work should recruit a larger and more diverse cohort, evaluate several application categories and device platforms with a fixed protocol, and include an external-app or leave-one-app-out test. A prospective, ethically approved user study is also needed to assess actual UX outcomes.
